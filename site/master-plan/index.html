Master plan

Context is the scarce resource.

Dalel AI · October 2026

Dalel builds data infrastructure for superintelligent models and for the agents that will work beside them. This document is the reason for the work and the order in which we will do it. Algorithms, hardware, and schemas belong in a later design. What follows is the discovery we are organizing a company around.

The constraint

Model capability is compounding. The machinery of context is not. An agent that can reason across a field still has to assemble that field: the papers, the statute, the person, the prior decision, the years in which a rule was alive. Today that assembly is a prompt, a bag of retrieved fragments, and whatever happened to fit.

Superintelligent systems will keep many objects in play at once. They will compare one thing with another thing, and they will return to the same corpus thousands of times a day. When that is the workload, the scarce resource is shared memory and the speed at which it can be addressed. Faster context management, and stricter data management, are the whole problem.

Objects

A vector database usually stores points. Each point may carry metadata, and a query may filter on it. That answers “which passage is close to this passage.” It does not represent the thing the passage is about.

We start from a different unit. Vectors are stored in a collection. An object is a subset of that collection. A film is an object. A viewer is an object. A paper, a court, a statute, and a decade are objects. Object types multiply, because the world is not one table.

The collection stays the physical store. Objects are how the collection is understood. Search can still ask for nearby vectors. It can also ask for a nearby object, which is a different question and the one agents will ask once they are trying to manage a situation rather than a paragraph.

One vector, several objects

The useful fact is that a single vector is often evidence for more than one thing.

The embedding of a film review is about the film and about the person who wrote it. A judicial opinion is about a case, a doctrine, a court, and a year. The year can be an object of its own: a period you can compare with another period. Forcing every vector to name a single parent throws that structure away, and then every later query has to reconstruct it by hand.

Membership in several object types is the ordinary case. The data model has to allow it from the beginning, or the public collections we want to publish will be bent around an early mistake.

Similarity between things

“Find a similar vector, possibly inside a filter” remains a necessary operation. It is the operation current systems already perform.

The operation they leave to the application is “find a similar object.” Which matter resembles this matter. Which researcher’s body of work sits near this one. Which stretch of legislation moved the way another stretch moved. Those questions compare sets of vectors. A case file and a scientific literature do not want the same comparison, so more than one distance between sets has to be available. The caller should be able to say what “similar thing” means for the object in front of them.

This is the query that makes context cheap. An agent spends its window on the objects that matter, because the database already knows how to rank objects.

Indexes that know what belongs together

Global indexes over a whole collection are still required. Scale lives there. What changes is that belonging is part of the index, alongside nearness.

Vectors that constitute the same object have a relationship even when they are far apart in embedding space. A film’s dialogue, its poster, and a review of it may sit in different neighborhoods and still be one object. An index that can use that relationship will retrieve the object. An index that only knows geometric neighbors will retrieve a cloud of fragments and leave the agent to glue them back together.

The same commitment covers where the bytes live. Large collections will sit on accelerators and on disk. The index has to be shaped for both. That is a direction of work, named here so the data model is not designed as if memory were free and uniform. The techniques themselves are for the technical design.

Public memory

A private index inside one lab does not fix a problem every agent will share. Science, law, and the news are common context. We will publish collections over them, on the object model above, with rate limits that keep research possible and the service standing.

Science: the articles researchers already treat as the record, beginning with corpora such as arXiv and PubMed. Law: legislation and case documents, so a system can find a similar matter. News: the public account of events. Further domains when the same pattern holds and the source can be redistributed honestly.

These collections are memory other systems query. They are a public utility for the agentic era, with the database underneath them good enough that “similar paper,” “similar case,” and “similar period” are direct questions.

Model state, after the collections

Retrieval is half of the cost of context. The other half is computation the model repeats. Open models recompute attention over the same prefixes: the same statute, the same paper, the same instructions. Once a prefix has been read, its key-value state is data. It can be stored, addressed, and reused.

We will do that after the database and the public collections exist, for open-source models. Shared model state belongs next to shared text. An agent should pay to read a document once.

Order of work

  1. The database. Collections of vectors. Objects as subsets. Many object types. Vectors that participate in several objects. Vector search, and search for a similar object, with more than one way to compare sets. Indexes over the collection that also connect the members of an object, built with accelerators and disk in mind.
  2. Public collections under rate limits: science, law, and news.
  3. Stored key-value state for open models.

Each stage is usable before the next one starts. The database has to be real before a public corpus is worth trusting. The corpus has to be real before cached model state has a shared place to live.

Who we are

Dalel AI is the company building this. The site exists to say so. There is no account system here, and no product to sign into. The work in front of us is the memory layer.
